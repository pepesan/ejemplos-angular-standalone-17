@Injectable: constructor frente a inject()

@Injectable() sirve en todas las versiones. Para código nuevo con inject(), la guía recomienda @Service() (Angular 22.0 o posterior); para inyección por constructor, @Injectable(). Ver Creating and using services.

Un único servicio @Injectable({ providedIn: 'root' }) con tres componentes. El número de instancia que muestra cada uno indica si comparten servicio. Pulsa los botones y observa qué valores cambian.

¿Cuándo es singleton y cuándo no?

A y B comparten la instancia raíz: es singleton. Da igual que A lo pida con el constructor y B con inject(): el modo de pedirlo no cambia el ámbito. C declara el servicio en providers y recibe una instancia nueva: no es singleton.

Dónde se registra el servicio y cuántas instancias hay
Dónde se registra¿Singleton?Instancias
@Injectable({ providedIn: 'root' }) o @Service() Sí Una para toda la aplicación (inyector raíz), disponible sin declarar nada más.
providers de un componente No Una por cada instancia del componente. Se destruye con él (componente C).
providers de una ruta No Una para esa ruta, sus componentes, guardas y resolvers (no se muestra en este ejemplo).
@Injectable() sin providedIn Según dónde lo declares No se registra solo: hay que declararlo en providers. Si no, Angular no encuentra el proveedor.
@Service({ autoProvided: false }) Según dónde lo declares Igual que el anterior: no se registra solo y hay que añadirlo a providers.

Limitaciones de cada forma de pedir el servicio

  • Constructor (constructor(private contador: ...)): el servicio debe ser @Injectable(). Es el estilo clásico y lo verás en mucho código existente.
  • inject(): funciona con @Service() y con @Injectable(). Solo se puede llamar en un contexto de inyección (constructor, inicializador de campo, factoría...). Fuera de él, Angular lanza un error.
