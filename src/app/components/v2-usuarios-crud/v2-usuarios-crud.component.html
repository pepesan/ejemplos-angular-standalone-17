CRUD de usuarios (V2)

Disponibilidad: @Service() estable desde Angular 22.0. El acceso a la API está en UsuariosApiService y la sesión usa el JWT del backend local.

CRUD de usuarios contra /api/usuarios (SQLite en memoria; arranca con npm run backend). Listado paginado, filtrable y ordenable en el servidor.

Buenas prácticas de acceso a la API que aplica este ejemplo
  1. Un solo punto de acceso: solo UsuariosApiService usa HttpClient.
  2. URL base configurable con InjectionToken (/api, relativa y vía proxy: sin CORS).
  3. Tipos explícitos (Usuario, ConsultaUsuarios, PaginaUsuarios); nada de any.
  4. Parámetros con params, no concatenados en la URL.
  5. Paginar, filtrar y ordenar en el servidor; el orden se valida con lista blanca (nunca SQL con texto del cliente).
  6. Observables fríos: el servicio no se suscribe; el componente usa takeUntilDestroyed.
  7. switchMap + debounceTime en el filtro: cancela peticiones obsoletas y no consulta en cada tecla.
  8. Errores traducidos (ErrorApi): mensaje, estado y errores por campo.
  9. JWT en un interceptor, en memoria; 401 → volver al login, 403 → mensaje de permisos.
  10. Autorización en el servidor: ocultar botones no basta; el backend rechaza escribir si no eres admin.
  11. UX: estados de carga, vacío y error; confirmar lo destructivo; no enviar dos veces; avisos anunciados con aria-live.
